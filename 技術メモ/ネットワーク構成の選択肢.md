# ネットワーク構成の選択肢

> 2026-11-13 時点の解説です。その後の変更は反映していないことがあります。

このプロジェクトで、API（ECS）から外への通信方式を選んだときに整理した内容です（2026-10-29）。
選んだ結果と理由は、[検討メモ.md](../検討メモ.md) の「8. 選定理由の記録」にあります。

料金は東京リージョンの概算です。構成を確定する前に、AWS の料金計算ツールで確認します。

## 1. 前提：VPC とサブネット

AWS では、自分専用のネットワーク（VPC）の中を、区画（サブネット）に分けて使う。

| 区画 | 性質 | 置くもの |
|---|---|---|
| パブリックサブネット | インターネットと直接つながる | ALB（入口）、NAT Gateway |
| プライベートサブネット | インターネットから直接は入れない | ECS（API）、Aurora（DB） |

ALB と Aurora は、2つ以上の区画（AZ：アベイラビリティーゾーン）にまたがって置く必要がある。

## 2. API が外へ通信する必要がある理由

API は次の AWS のサービスにアクセスする。

- ECR：アプリのイメージの取得
- CloudWatch Logs：ログの送信
- Bedrock：生成 AI の呼び出し
- Secrets Manager など：パスワードなどの取得

## 3. 4つの方式

| 方式 | 内容 | 起動中の料金 | 月40時間の場合 | 停止を忘れた場合（月） |
|---|---|---|---|---|
| A. API をパブリックに置く | API に公開アドレスを持たせ、直接外へ通信させる。外からのアクセスは、セキュリティグループで ALB からのものだけ許可する | 約 $0.005/時間（公開アドレスの料金） | 約 $0.2 | 約 $4 |
| B. プライベート＋NAT Gateway | 外への通信を、NAT Gateway（外向き専用の出口）を通す | 約 $0.062/時間＋通信量 | 約 $2.5 | 約 $45 |
| C. プライベート＋VPC エンドポイント | インターネットを使わず、AWS のサービスへの専用の通り道を、サービスごとに作る | 約 $0.14/時間（5種類 × 2区画） | 約 $5.6 | 約 $100 |
| D. プライベート＋NAT インスタンス | NAT の役割を、小さな EC2 に担わせる | 約 $0.005/時間 | 約 $0.2 | 約 $4 |

補足

- S3 用のゲートウェイ型エンドポイントは無料。ECR のイメージの実体は S3 にあるため、B でも併用すると NAT Gateway を通る通信量を減らせる。
- NAT Gateway を区画ごとに置くと、料金は区画の数だけ増える。

## 4. 構成図（B を採用した場合）

```
インターネット
     │
 ┌───┼──────────────── VPC ─────────────────────┐
 │   ▼                                            │
 │ [パブリック]  ALB（入口）    NAT Gateway（出口）│
 │                 │               ▲              │
 │                 ▼               │              │
 │ [プライベート] ECS（API）──────┘──▶ ECR / Bedrock など
 │                 │                              │
 │                 ▼                              │
 │ [プライベート] Aurora（DB）                     │
 └────────────────────────────────────────────────┘
```

## 5. 常設層と起動層の分け方（案）

| 層 | 含めるもの | 理由 |
|---|---|---|
| 常設層 | VPC、サブネット、ルートテーブル、セキュリティグループ、Aurora | 無料、または休止できる |
| 起動層 | ALB、NAT Gateway、ECS サービス | 起動している間、時間あたりの料金がかかる |
