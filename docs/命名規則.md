# 命名規則

このプロジェクトで使う名前の規則です。名前を付ける前に、ここを見ます。規則は、その名前が必要になった時期に節を足していきます。

---

## 1. 全体の原則（2026-11-14 に決定）

| 対象 | 規則 | 理由 |
|---|---|---|
| 文書（仕様書、技術メモ、ADR など） | 日本語 | 読み手が日本語で読む。今ある文書と合わせる |
| コード、ブランチ、AWS の名前 | 英小文字・数字・ハイフン | 道具によっては日本語や大文字を使えない。URL やコマンドで扱いやすい |
| AWS のリソース名 | `tech-notes` で始める | IAM の権限を「名前の接頭辞」で絞る（仕様書 第6章）ときに、1つの規則で済む |
| SSM パラメータのパス | `/tech-notes/` で始める | 同上 |

---

## 2. GitHub（2026-11-14 に決定）

| 対象 | 規則 | 例 |
|---|---|---|
| マイルストーン | `段階N：名前`（仕様書 9.1 の段階） | `段階0：準備` |
| ラベル | 日本語 | `未決事項` |
| Issue の題名 | 日本語で「〜する」の形 | `権限設定をリポジトリに入れる` |
| ブランチ | `Issue番号-英語の短い説明` | `3-add-permissions` |
| コミットメッセージ、PR の題名 | `種類: 日本語で「〜する」の形`（3節） | `docs: 権限設定の技術メモを追加する` |

GitHub が最初から用意した英語のラベル（`bug` など）は、段階0では1つも使わなかったので、10個とも保管（Archive）しました（2026-11-15）。必要になったら、ラベルの画面の Archived のタブから戻します。

ブランチ名を英語にするのは、`gh issue develop` などで Issue の題名から自動で作ると、日本語のブランチ名になってしまうためです。

---

## 3. コミットメッセージと PR の題名

Squash でマージするので、PR の題名が、そのまま main のコミットの1行目になります。形は Conventional Commits に合わせます。作業用ブランチの途中のコミットも、同じ形にします。

```
種類: 日本語で「〜する」の形
```

| 種類 | 使う場面 | 例 |
|---|---|---|
| `feat` | API の機能を足す | `feat: 記事の一覧を返す API を追加する` |
| `fix` | 不具合を直す | `fix: 要約が空のときに 500 を返す不具合を直す` |
| `docs` | 文書だけを変える | `docs: 権限設定の技術メモを追加する` |
| `infra` | Terraform を変える | `infra: 準備用の Terraform を追加する` |
| `ci` | GitHub Actions を変える | `ci: lint のワークフローを追加する` |
| `refactor` | 動きを変えずにコードを整理する | `refactor: 要約の処理を別の関数に分ける` |
| `test` | テストだけを足す、直す | `test: 記事の保存のテストを追加する` |
| `chore` | 上のどれにも当たらない雑務（設定ファイルなど） | `chore: .gitignore に Terraform の項目を足す` |

- 1つの PR に複数の種類が混ざるときは、いちばん主な変更の種類にします。
- `infra` は Conventional Commits の標準の一覧にはない、このプロジェクトで足した種類です。
- AI が関わったコミットには、本文の最後に `Co-Authored-By:` を付けます（CLAUDE.md）。

## 5. Terraform（2026-11-15 に決定）

| 対象 | 規則 | 例 |
|---|---|---|
| フォルダ | `terraform/層の名前/`。1つのフォルダが1つの state になる | `terraform/bootstrap/` |
| 層の名前 | 準備用は `bootstrap`、常設層は `persistent`、起動層は `launch`。タグの `Layer` にも同じ名前を使う | `Layer=persistent` |
| タグ | すべてのリソースに `Project=tech-notes` と `Layer=層の名前` を付ける（仕様書 6.1） | |
| state のバケット | `tech-notes-tfstate`。名前は世界で1つだけなので、消さない前提で使う | |
| 予算 | `tech-notes-monthly` | |

親フォルダを `infra/` ではなく `terraform/` にしたのは、Terraform で作るものと、アプリの配布物の境目をはっきりさせるためです。タスク定義のひな形などのアプリの配布物は、`deploy/` に置く予定です。

バケットの名前にアカウント ID を入れなかったのは、アカウント ID を公開のファイルに書かない決まりがあるためです。名前が空いていることを確かめてから決めました。

## 6. DB（2026-11-18 に決定）

| 対象 | 規則 | 例 |
|---|---|---|
| テーブル | 英小文字の複数形。単語の区切りはアンダースコア | `notes` |
| 列 | 英小文字。単語の区切りはアンダースコア | `created_at` |
| マイグレーションのファイル | `migrations/5桁の番号_動詞_対象.sql`。番号は順に1つずつ増やす | `migrations/00001_create_notes.sql` |
