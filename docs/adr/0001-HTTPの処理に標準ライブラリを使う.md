# 0001. HTTP の処理に標準ライブラリを使う

2026-11-15 に決定（#23）

## 比較した選択肢

| 選択肢 | 内容 |
|---|---|
| A. 標準ライブラリ（`net/http`） | Go 1.22 から、`GET /notes/{id}` のように、メソッドとパスの中の値を指定できる |
| B. chi | 標準ライブラリとほぼ同じ書き方で、ミドルウェアなどを差し込みやすくする軽い部品 |
| C. Gin | 入力の検証や JSON の扱いまでそろったフレームワーク。広く使われていて、日本語の情報も多い |

## 決定

A. 標準ライブラリを使う。

## 理由

- コードは AI が書き、利用者はテストケースを挙げて動きを確かめる、という進め方にした。標準ライブラリなら、リクエストを受けてから応答を返すまでの仕組みが隠れず、確かめやすい
- 利用者はアプリケーションの開発に慣れていないので、どのフレームワークも土台にしている `http.Handler` の仕組みから学べる
- 外部の部品が増えないので、段階2で入れる脆弱性の検査の対象が少なくて済む
- 段階6の OpenTelemetry の計測は、標準のハンドラーに対応した部品をそのまま使える

## 引き受ける課題

- 入力の検証や、JSON のエラーの形は、自分で書く必要がある（#26）
- Gin のような、会社でよく使われるフレームワークの書き方には、このプロジェクトでは慣れられない

## 発展

- ミドルウェアが増えて書くのが大変になったら、chi への置き換えを検討する。chi は標準のハンドラーをそのまま使えるので、置き換えは小さく済む
