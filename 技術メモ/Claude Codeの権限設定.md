# Claude Code の権限設定

Claude Code が「実行してよい操作」と「実行してはいけない操作」を、設定ファイルで決める仕組みです。仕様書 6.3 の「AI の操作」の関所は、この仕組みで作ります。

---

## 1. なぜ必要か：「約束」と「鍵」の違い

| | CLAUDE.md に書く | 権限設定に書く |
|---|---|---|
| たとえ | 「金庫を開けないでね」というメモ | 金庫の鍵を渡さない |
| 仕組み | AI が読んで、守ろうとする | Claude Code 本体が、実行の直前に止める |
| 破られる場合 | AI の勘違い、指示の読み落とし、長い会話で指示が薄れる | 設定の形に当てはまらない書き方をされた場合だけ |

CLAUDE.md は「お願い」、権限設定は「仕組み」です。大事な禁止事項は、両方に書きます。

---

## 2. ルールの3種類と、調べる順番

| 種類 | 意味 |
|---|---|
| `deny` | 実行させない。確認の画面も出さない |
| `ask` | 実行する前に、毎回、利用者に確認する |
| `allow` | 確認なしで実行してよい |

Claude Code は、操作のたびに **deny → ask → allow** の順に調べ、最初に当てはまったものに従います。

- deny に当てはまれば、allow に同じものが書いてあっても実行されない
- どれにも当てはまらなければ、そのときのモードに従う（通常のモードなら確認、自動のモードなら AI の判断）
- **deny は、どのモード（auto mode を含む）でも最優先**で効く

---

## 3. 設定ファイルの置き場所

| ファイル | 効く範囲 | Git に入るか |
|---|---|---|
| `~/.claude/settings.json` | 自分のすべてのプロジェクト | 入らない |
| `.claude/settings.json` | このプロジェクト（共有） | 入る |
| `.claude/settings.local.json` | このプロジェクト（自分だけ） | 入れない（.gitignore 済み） |

deny のルールは、すべてのファイルの分が合わせて効きます。どこか1か所で deny されれば、止まります。

---

## 4. ルールの書き方

### コマンド（Bash）

| 書き方 | 当てはまる例 | 当てはまらない例 |
|---|---|---|
| `Bash(gh pr merge*)` | `gh pr merge 3`、`gh pr merge 3 --squash` | `gh pr view 3` |
| `Bash(terraform * apply*)` | `terraform -chdir=infra apply` | `terraform plan` |
| `Bash(git push * main*)` | `git push origin main`、`git push --dry-run origin main` | `git push origin 5-add-readme` |

- `*` は「何文字でも、何でも」です。途中に置くこともできます。
- `&&` や `;` でつないだコマンドは、1つずつ調べられます。`cd infra && terraform apply` も、後半が deny のルールに一致して止まります。

### ファイル（Edit）

| 書き方 | 意味 |
|---|---|
| `Edit(.claude/settings.json)` | 今いるフォルダから見た、このファイルの書き換えを止める |
| `Edit(~/.claude/settings.json)` | ホームフォルダのこのファイルの書き換えを止める |

`Edit(...)` のルールは、ファイルを書く道具（Edit と Write）の両方に適用されます。

## 5. このプロジェクトの設定（2026-11-14 に決定）

### 考え方：権限設定は「シートベルト」

権限設定は、コマンドの文字の形だけを見て止めます。同じ操作でも書き方はいくらでも変えられるので、抜け道を1つずつ塞ごうとすると、ルールが増え続けても塞ぎきれません（もぐら叩き）。

そこで役目を「**うっかりの事故を防ぐこと**」に絞り、**普通の書き方を、広めに1行で止める**ことにしました。わざわざ抜け道を使う場合への備えは、別の守り（6節）に任せます。

### 設定の中身（`.claude/settings.json`）

| 種類 | ルール | 意味 | 決めた理由 |
|---|---|---|---|
| deny | `Bash(terraform apply*)` | apply させない | 仕様書 6.3 |
| deny | `Bash(terraform destroy*)` | destroy させない | 仕様書 6.3 |
| deny | `Bash(gh pr merge*)` | PR をマージさせない | 仕様書 6.3 |
| deny | `Bash(git push*)` | push はすべて利用者が行う | main への push・強制 push を、抜け道なく1行で止められる。git は手打ちで理解したいという希望にも合う |
| deny | `Bash(gh workflow run*)` | ワークフローの手動実行は、すべて利用者が行う | main かどうかを文字の形で確実に見分けるのは難しい。main での実行（起動など）も料金のかかる変更 |
| deny | `Bash(gh repo delete*)` | リポジトリを削除させない | 戻せない |
| deny | `Bash(gh repo edit*)` | リポジトリの設定（公開範囲など）を変えさせない | 影響が大きい |
| ask | `Edit(.claude/settings.json)` | 権限設定の書き換えは、差分を見て利用者が許可する | AI が自分で制限を緩められないようにする。手で編集して JSON の文法を誤り、設定がまるごと効かなくなる事故も防ぐ |
| ask | `Edit(~/.claude/settings.json)` | 同上（全体の設定） | 同上 |

### 相談の結果、入れなかったもの

| 候補 | 入れなかった理由 |
|---|---|
| AWS CLI（`aws`）を毎回確認 | 使うのはほとんど読み取りのため。AWS を変更する操作は、CLAUDE.md の約束どおり、実行前に内容を示して承認を得る |
| Cloudflare の API への接続 | CLAUDE.md の「触れない」で扱う |
| `rm -rf` などの手元の一括削除 | 一時ファイルの片付けで日常的に使う。コミット済みのものは Git から戻せる |
| `terraform -chdir=… apply` や、API を直接呼ぶマージなどの抜け道 | 追いかけると際限がない。6節のほかの守りに任せる |

## 6. この仕組みの限界と、ほかの守り

1. **文字の形で見分けるだけ**です。普通でない書き方（例：`terraform -chdir=infra apply`）は止まりません。
2. **シェルを経由したファイルの書き換えは止められません**。`Edit(...)` のルールは、ファイルを書く道具を止めるだけです。
3. **止めすぎることがあります**。止めすぎは安全側なので、困ったら調整します。

このため、権限設定は**多層防御の1枚目**として使います。

| 守り | 止めるもの | 作る時期 |
|---|---|---|
| 1. 権限設定（これ） | AI が手元で、普通の書き方で実行すること | 段階0の手順3 |
| 2. ブランチ保護 | main への直接の push と、PR なしのマージ（GitHub 側で拒否） | 段階0の手順4 |
| 3. IAM の条件 | main 以外から AWS を書き換えること | 段階3 |
| 4. CLAUDE.md | 上のどれにも当たらない操作（約束として） | 済み |

## 7. 確かめた結果（2026-11-14）

書いた直後に、仮に止まらなくても害のないコマンドで確かめ、すべて止まりました。

| 試したコマンド | 結果 |
|---|---|
| `jq . .claude/settings.json` | 文法は正しい |
| `git push --dry-run origin main` | 止まった（`--dry-run` は送ったふりだけで、実際には送らない） |
| `gh pr merge 999` | 止まった |
| `terraform apply -help` | 止まった |
| `gh workflow run nothing.yml` | 止まった |

## 8. 戻し方・確認の仕方

- ルールを変える：`.claude/settings.json` を書き換える（AI が書き換えるときは、差分を見て許可する）
- すべて外す：`.claude/settings.json` を削除する
- 今効いているルールを見る：Claude Code の中で `/permissions` と打つ
