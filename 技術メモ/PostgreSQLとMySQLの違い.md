# PostgreSQL と MySQL の違い

このプロジェクトで DB エンジンを選んだときに整理した内容です（2026-10-29）。
選んだ結果と理由は、[検討メモ.md](../検討メモ.md) の「8. 選定理由の記録」にあります。

## 1. 共通していること

- どちらも SQL を使うリレーショナル DB で、表（テーブル）にデータを保存する
- 基本的な SQL（`SELECT`、`INSERT` など）は、ほぼ同じように書ける
- どちらも無料で使え、長い歴史があり、大規模なサービスでの実績がある

「どちらでなければ作れない」という差はない。違いが出るのは、細かい挙動と運用。

## 2. 設計の考え方の違い

| | PostgreSQL | MySQL |
|---|---|---|
| 生まれ | 大学の研究プロジェクトから生まれた | Web サービス向けに、速さと手軽さを重視して作られた |
| 考え方 | 正確さ・厳密さと、拡張できることを重視する | シンプルさと、読み込みの速さを重視する |
| 普及の歴史 | 近年、新しいサービスでの採用が増えている | 2000年代から、日本の大規模 Web 企業で広く使われてきた |

## 3. 開発するときに感じる違い

| 項目 | PostgreSQL | MySQL |
|---|---|---|
| 登録した行をそのまま返す | `INSERT ... RETURNING id` で、登録した ID を1回で受け取れる | `RETURNING` がないため、登録したあとに別の方法（`LAST_INSERT_ID()`）で ID を取得する |
| 大文字と小文字の区別 | 区別する（`'Go'` と `'go'` は別のもの） | 標準の設定では区別しない（同じとみなす） |
| テーブル構造の変更（DDL）を取り消せるか | トランザクションの中で実行でき、途中で失敗しても、すべて元に戻せる | DDL はその場で確定する。途中で失敗すると、中途半端な状態が残ることがある |
| 登録と更新をまとめて行う（upsert） | `INSERT ... ON CONFLICT` | `INSERT ... ON DUPLICATE KEY UPDATE` |
| JSON の扱い | `jsonb` 形式で保存でき、中身で検索するためのインデックス（GIN）も作れる | JSON 型はあるが、検索を速くするには工夫が要る |
| インデックスの種類 | 種類が多い（部分インデックス、式インデックス、GIN、GiST、BRIN など） | B-tree が中心。全文検索用と、関数を使ったインデックスもある |
| 機能の追加（拡張） | 拡張機能で、あとから機能を追加できる（例：pgvector、pg_stat_statements） | 拡張の仕組みは限られる |
| 同時に更新したときの標準の挙動（分離レベル） | 他人が確定した変更は、すぐに見える（Read Committed） | 処理中は、最初に見た状態が続く（Repeatable Read） |

## 4. 運用するときの違い（SRE の観点）

| 項目 | PostgreSQL | MySQL |
|---|---|---|
| 接続の重さ | 接続1つごとに、独立した処理（プロセス）を立ち上げる。そのため接続が重く、大量の接続に弱い。コネクションプールや RDS Proxy などで対策する | 接続ごとに軽い処理（スレッド）で対応するため、比較的軽い |
| 不要データの掃除 | 更新・削除で古いデータが残る。それを定期的に掃除する仕組み（VACUUM）がある。基本は自動（autovacuum）だが、監視と調整が必要になることがある | 古いデータは別の仕組み（undo ログの purge）で片付けられるため、意識する場面は少ない |
| Aurora 固有の機能 | Aurora PostgreSQL として利用できる | Aurora MySQL にしかない機能が一部ある（データを過去の時点に巻き戻す Backtrack など） |

## 5. このプロジェクトとの関係

| 観点 | 関係 |
|---|---|
| 目的2「安全なリリース」 | DDL を取り消せるので、マイグレーションを安全に行いやすい |
| 目的3・4「可観測性」「改善」 | pg_stat_statements で、遅いクエリを特定しやすい |
| 目的5「AI 機能」 | 発展の段階で、pgvector により意味検索へ広げられる |
| 運用の学び | 接続数の管理と VACUUM が、SRE として説明できる題材になる |
| 注意点 | 将来 MySQL の現場に入ったときは、大文字・小文字の扱いや、DDL の挙動の違いに注意する |
